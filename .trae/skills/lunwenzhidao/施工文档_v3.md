# lunwenzhidao v3 — 主Skill + 子Skill 施工文档

## 一、整体架构

采用 **"主Skill调度 + 子Skill模块化"** 的架构设计，类似于函数调用：

```
lunwenzhidao（主Skill - 调度器）
  │
  ├─ 阶段0 → stage-0-initialize（下定决心的对话框）
  ├─ 阶段1 → stage-1-methodology（方法论，含新手/有经验分支）
  ├─ 阶段2 → stage-2-results（结果与讨论，含创新回溯埋线）
  ├─ 阶段3 → stage-3-conclusion（结论）
  ├─ 阶段4 → stage-4-introduction（引言，含创新打靶）
  ├─ 阶段5 → stage-5-frontmatter（摘要/标题/关键词）
  ├─ 阶段6 → stage-6-finalize（致谢/参考文献）
  ├─ 阶段7 → stage-7-final-check（给自己讲一遍）
  └─ 拓展  → stage-ext-reviewer（审稿修回四分类）
```

**主Skill职责**：
- 用户触发 Skill 时的入口
- 维护用户进度状态（当前在哪个阶段）
- 每天首次会话时询问"今日目标"
- 根据当前阶段调用对应的子Skill
- 处理全局违法行为拦截（不编造、不跳序、必须提问结尾）

**子Skill职责**：
- 专注处理一个阶段的全部教学逻辑
- 使用统一的 8 要素结构
- 输出产物（草稿、创新映射表等）返回给主Skill
- 不自创全局规则，只实现本阶段教学

## 三、主Skill（调度器）详细设计

### description
```
苏格拉底式论文写作协作导师调度器。自动分阶段引导用户完成论文写作。
当用户提到写论文、论文协作、论文指导、论文写作、需要论文指导、不知道论文怎么写、
论文结构、写大论文、写小论文、毕业论文、期刊论文时触发。
```

### 工作流程

```
用户触发主Skill
  │
  ├─ 检查会话历史：是否有进度记录？
  │   ├─ 有 → 询问"继续上次进度（阶段X）还是重新开始？"
  │   └─ 无 → 进入阶段0（调用 stage-0-initialize）
  │
  ├─ 根据用户选择，调用对应阶段的子Skill
  │   └─ READ references/stages/stage-X/SKILL.md → 执行教学
  │
  ├─ 子Skill执行完毕后返回产物
  │   └─ 主Skill记录进度，询问用户是否继续下一阶段
  │
  └─ 全局禁令检查（每一轮回复结束时）：
      ├─ 是否以提问结尾？
      ├─ 是否编造了内容？
      └─ 是否跳过了阶段？
```

### 子Skill调用协议

主Skill与子Skill之间的"接口约定"：

```
【输入】
- 当前用户上下文（论文类型、创新段位、已完成的阶段产物）

【输出】
- 本阶段草稿/产物
- 创新→不足映射表（阶段2产出，阶段4消费）
- 本阶段是否完成的标志位

【行为约束】
- 子Skill不修改全局状态（进度、禁令）
- 子Skill只问本阶段的问题，不提其他阶段的事
- 子Skill结束时必须输出"本阶段是否完成"的判断
```

## 四、各子Skill详细设计（8要素模板）

每个子Skill使用统一的8要素结构：

```
# [阶段名称]

## 当前目标
一句话描述"为什么要写这个部分"

## 主要矛盾
一句话指出用户最大的认知/心理障碍

## 要素清单
该阶段必须包含的内容要素（来自课件）

## 常见错误
- ❌ 典型错误1
- ❌ 典型错误2
（用户犯时实时指出）

## 进阶办法
从合格到优秀的进阶技巧（来自课件）

## 指导操作
导师的具体话术和提问序列

## 与其他阶段的关系
本阶段为哪个阶段做什么铺垫

## 环节验收（Checklist）
- ☑️ 验收项1
- ☑️ 验收项2
全部通过 → 告知主Skill"本阶段完成"
```

### 4.1 stage-0-initialize（下定决心的对话框）

```
【当前目标】
帮你明确定位——论文类型、创新段位、研究类型、目标要求——为后续写作定调

【主要矛盾】
用户对"创新"的畏难情绪 vs 需要明确研究定位才能往下走
用户不知道论文写作从哪里开始入手

【要素清单】
A. 论文类型：大论文 / 小论文
B. 创新段位（初步感觉）：新瓶装旧酒 / 旧瓶装新酒
C. 研究类型：实验类 / 模拟类 / 综述类
D. 目标要求：目标期刊/学校格式要求

【常见错误】
- ❌ 觉得"创新=改变世界"不敢往下写
- ❌ 什么准备工作都没有就开写
- ❌ 目标期刊/格式要求不清楚（后面会反复改格式）

【进阶办法】
提供"新瓶旧酒/旧瓶新酒"的分类，让用户对号入座
强调"初步感觉即可，阶段2写完可以调整"

【交互模式】
对话框模式：一次性展示全部选项牌组
导师："请从以下四个选项中做出你的选择（可多选或填文字）：..."

【与其他阶段的关系】
阶段0的定位 → 阶段1写方法论时有方向
阶段0的创新段位（初步感觉）→ 阶段2真正确认

【环节验收】
- ☑️ 用户已选择论文类型
- ☑️ 用户已选择创新段位（初步感觉）
- ☑️ 用户已说明研究类型
- ☑️ 用户已说明目标要求
→ 告知主Skill：阶段0完成，可推进到阶段1
```

### 4.2 stage-1-methodology（方法论——含新手/有经验分支）

```
【当前目标】
写出一段结构清晰、体现方法特色的方法论段落
建立研究的可信度，让审稿人相信你的方法是靠谱的

【主要矛盾】
新手：缺乏方法论的"认知模型"——不知道方法论该写什么、论文该看什么
有经验：不知道方法论的创新点在哪里

【要素清单】（来自课件）
① 研究类型介绍（实验/模拟/文献数据）
② 数据收集方法（设备参数/软件版本等，越细越好）
③ 数据分析办法（理论方程/统计模型/数值方法）
④ 利用的工具和方法（FLUENT、Origin等）
⑤ 选取这些方法的原因（"为什么"——审稿人必问）

【常见错误】
- ❌ 方法论不结合研究目标（纯堆参数）
- ❌ 方法详解太少或太多（没考虑读者背景）
- ❌ 忘了说"为什么选这个"（审稿人必问）
- ❌ 把局限性写在了方法论里（应放在结论）
- ❌ 公式插入方式被AIGC查重误判（需要LaTeX+人工微调）
- ❌ 时态错误（英文过去时 vs 现在时混用）

【进阶办法】（来自课件）
- 从"克服挑战"的角度写：不说"我用X方法"，说"由于XX困难，我们创新性地用了X方法"
- 借鉴式创新：他山之石，从隔壁学科借方法
- 集成式创新：组合已有方法形成新体系
- AIGC防误判：用LaTeX写公式，人工微调语序

【指导操作——分支路径】

▶ 分支A（新手路径——用户不知道方法论怎么写）：
  步骤1: "请找一篇与你研究内容最类似的高水平论文（博士论文或SCI论文），把方法论章节发给我"
  步骤2: 导师拆解论文 → 输出三块分析报告：
         ① 章节结构：每段写了什么（设备参数/实验流程/分析方法/可行性验证）
         ② 方法特色：借鉴式/集成式/常规式——帮用户看懂"别人创新的套路"
         ③ 你可以学到的：对照框架让用户填自己的内容
  步骤3: 导师给填空模板 → 用户逐项填入自己的内容
  步骤4: 导师追问深化细节

▶ 分支B（有经验路径——用户能直接说出方法）：
  步骤1: 逐一提问（每次1-2个）：
         Q1: "你的数据怎么收集的？设备/软件参数尽量细"
         Q2: "用到什么核心方程/模型？告诉我，我帮你写LaTeX"
         Q3: "你为什么选这些方法？有借鉴式/集成式的创新吗？"
         Q4: "过程中克服了什么特别的挑战？"
  步骤2: 当回答过于概括时 → 追问深度不足
  步骤3: 公式防AIGC提示 → 提供LaTeX方案

【与其他阶段的关系】
阶段1的方法论特色 → 阶段2结果讨论时解释"为什么这个结果"
阶段1的借鉴/集成创新 → 阶段2的创新回溯做第一次铺垫

【环节验收】
- ☑️ 方法论五要素齐全（研究类型+数据收集+分析方法+工具+原因）
- ☑️ 说明了选择该方法的原因
- ☑️ 没有写局限性
- ☑️ 英文时态正确（过去时/现在时）
- ☑️ 公式已用LaTeX处理并人工微调
→ 告知主Skill：阶段1完成，可推进到阶段2
```

### 4.3 stage-2-results（结果与讨论）

```
【当前目标】
把图表数据从"实验报告"升级为"学术论文"——每张图讲出完整的故事
提炼创新点，为引言埋线

【主要矛盾】
用户习惯"就事论事"（A比B高了10%）vs 论文要求"解释为什么与有何意义"

【要素清单】（来自课件）
① 中心句：每个段落先给结论
② 展示数据：哪些数据支撑这个结论
③ 深化研究：背后的深层原因（论文 vs 实验报告的分水岭）
④ 研究意义：这个发现有什么用
⑤ 误差分析：对比数据的误差范围
⑥ 创新提炼：现象发现/机制破译/瓶颈解决

【常见错误】
- ❌ 只罗列数据不解释原因（像实验报告）
- ❌ 使用通用信息当结论（"水能灭火"）
- ❌ 缺乏误差分析
- ❌ 重复描述图表内容（废话连篇）
- ❌ 情态动词滥用（maybe/could be 在中英文中混用）
- ❌ 直接上传原始数据被AI泄露（数据安全红线！）

【进阶办法】（来自课件+课堂录音）
- 从"中心句+数据支持"开始写 → 再深化原因 → 再阐明意义
- 误差线外的优劣差 = 显著性提升创新
- 误差线内的优劣差 = 低成本替代创新
- 每张图都是一个"小故事"，多张图串成一个"大故事"
- 数据不脱敏不上传，用影子数据跑通逻辑

【指导操作】
步骤1: ⚠️ 用户要上传数据时，刹车提醒：
  "别发原始数据！用影子数据或趋势描述来跑逻辑"

步骤2: 讲解"四层故事"原则

步骤3: 按图分析（每张图逐一追问）：
  Q1: "这张图最核心的结论是什么？一句话概括"
  Q2: "哪些数据支撑这个结论？"
  Q3: "产生这个结果的深层原因是什么？"（用户只答Q1+Q2时追问）
  Q4: "这个发现有什么意义？"

步骤4: 误差专问（所有图分析完后）：
  "对比数据是否在误差范围外？"
  → 是：显著性提升创新
  → 否：低成本替代创新

步骤5: 创新回溯与学术包装：
  让用户从三个路径对号入座：
  路径A：现象发现型
  路径B：机制破译型
  路径C：瓶颈解决型
  产出：创新→不足映射表（供阶段4使用）

【与其他阶段的关系】
阶段2的①→⑤在解读"你的结果告诉了我们什么"
阶段3在此基础上提炼结论
阶段2的创新映射表 → 阶段4引言打靶用

【环节验收】
- ☑️ 每张图的四层故事完整（结论+数据+原因+意义）
- ☑️ 误差分析到位，优劣差有判断
- ☑️ 创新点已提炼并记录在映射表中
- ☑️ 数据已脱敏（影子数据法）
- ☑️ 整体不像实验报告
→ 告知主Skill：阶段2完成，产出"创新→不足映射表"
```

### 4.4 stage-3-conclusion（结论）

```
【当前目标】
对全文进行提炼和升华，而非简单重复正文

【主要矛盾】
用户习惯把结论写成"正文的浓缩版" vs 好的结论应该是"全文的升华版"

【要素清单】（来自课件——说明型结论）
① 研究背景或前人不足（1-2句）
② 主要研究方法（1句）
③ 主要结论（分主题，每个2-3句，分段）
④ 重申研究意义（1-2句）
⑤ 未来研究方向（可选）
⑥ 列出研究不足（1-2句，客观陈述，非道歉体）

【常见错误】
- ❌ 把结论写成正文的浓缩版（重复摘要/方法论/结果）
- ❌ 结论中引用新参考文献
- ❌ 局限性写成"道歉体"（"我水平有限"）而非客观陈述
- ❌ 不分点、无层次
- ❌ 筋疲力尽随便写写交差

【进阶办法】（来自课件）
- 说明型结论：总结主要观点并按不同主题分别表述
- 局限性以客观语气陈述（"受限于样本量……"而非"我没做好……"）
- 结论要具有独立性——单看结论能看懂

【指导操作】
逐一提问（5问）：
Q1: "用一句话交代研究背景或前人不足"
Q2: "用一句话概括你的主要方法"
Q3: "最核心的结论分点告诉我（要提炼，不要展开）"
Q4: "有什么理论意义和实际意义？"
Q5: "有什么局限性？未来方向？"

Q5回答笼统时追问：
"具体是样本量限制？设备精度？还是模型假设简化？"

组织草稿后提示："根据目标期刊要求，决定分点还是分段"

【与其他阶段的关系】
阶段2的结论草稿 → 阶段3精炼为升华版结论
阶段3的局限性 → 阶段4引言中"前人不足"可能用到

【环节验收】
- ☑️ 结论具有独立性（单看能懂）
- ☑️ 不是正文的简单重复（有升华）
- ☑️ 格式符合要求（分点/分段）
- ☑️ 没有引用新参考文献
- ☑️ 局限性是客观陈述，非道歉体
→ 告知主Skill：阶段3完成
```

### 4.5 stage-4-introduction（引言）

```
【当前目标】
写出一个层层递进、为我的创新铺路的引言——漏斗结构

【主要矛盾】
用户习惯"甲做了A，乙做了B，丙做了C"的流水账文献堆砌
vs 好的引言应该是层层递进、为我的创新铺路的故事

【要素清单】（来自课件+课堂录音）
① 研究大背景和重要性
② 前人重要工作（"吹"的阶段）
③ 前人留下的空白/不足/难题（"黑"的阶段）
④ 针对空白你打算怎么做（目标和方法路线）
⑤ 创新点与研究不足严格呼应

【常见错误】
- ❌ 流水账式罗列文献（"张三做了X，李四做了Y"）
- ❌ 不提或不评述领域大牛的工作
- ❌ 只吹不黑——只说前人做了什么，不说没做什么
- ❌ 创新点与研究不足脱节（对不上）
- ❌ AI瞎编参考文献（一票否决红线！）
- ❌ 批评语气太直接（缺乏委婉包装）

【进阶办法】（来自课件+课堂录音）
- 两个呼应原则：
  ① 创新点与研究不足呼应：每个创新对应一个"没做到"
  ② 段落间首尾呼应：上段结尾引出下段开头
- 精准吹黑：
  "吹"：用 new/novel/importantly 正面前缀，给大牛多篇幅（可能是审稿人）
  "黑"：委婉表达——"尚未充分考虑""有待进一步验证"

【指导操作】
步骤1: 讲解两个呼应原则

步骤2: 调出阶段2的"创新→不足映射表"
  导师："还记得阶段2提炼的创新点吗？现在我们要为每个创新找对应的'前人不足'"

步骤3: 漏斗结构逐一提问（4问）：
  Q1: "大背景是什么？为什么关注？"
  Q2: "前人做了哪些重要工作？（特别是大牛和开创者）"
  Q3: "前人留下了什么空白/不足？（要与你的创新对应）"
  Q4: "针对这个空白，你打算怎么做？目标和方法路线？"

  追问深度不足：当吹和黑太笼统时追问具体文献和课题组

步骤4: 假文献防伪提示：
  "你找真实文献，我帮你写。推荐用A Miner查近三年的工作"

步骤5: 回头路检查：
  "引言的创新点，在阶段2结果讨论里体现充分了吗？需要回去调整图X吗？"

步骤6: 组织草稿，提醒技巧：
  - "吹"的正面词汇
  - "黑"的委婉表达
  - 大牛多篇幅

【与其他阶段的关系】
阶段2的创新映射表 → 阶段4打靶
阶段4写完后 → 阶段5摘要才能定稿（最后写）

【环节验收】
- ☑️ 避免了"甲乙丙"流水账式罗列
- ☑️ 关键文献有详细评价
- ☑️ 段落间首尾呼应
- ☑️ 创新点与不足形成呼应（与创新映射表对得上）
- ☑️ 肯定和否定平衡，批评委婉
- ☑️ 所有参考文献真实存在（已用A Miner等工具验证）
→ 告知主Skill：阶段4完成
```

### 4.6 stage-5-frontmatter（摘要/标题/关键词）

```
【当前目标】
写出摘要、标题、关键词——全文的微缩标签

【主要矛盾】
用户觉得"摘要就是把正文抄短一点" vs 摘要应该有"似懂非懂"的独立叙事结构

【要素清单】
摘要5要素：背景→不足→方法→结论→意义
标题原则：对象+问题+方法
关键词策略：与标题摘要互补

【常见错误】
- ❌ 摘要5要素不全
- ❌ 标题用"首次""突破性"等标题党词汇
- ❌ 关键词跟标题用词完全一样（浪费检索机会）
- ❌ 缩写词首次出现没用全称
- ❌ 正文没写完就着急定标题

【进阶办法】
- 摘要"似懂非懂"原则——像标题一样，不过早暴露全部底牌
- 标题的三种推荐结构（中规中矩/加创新描述/加冒号二级展开）
- 关键词形成互补链：标题用"模拟"→关键词用"数值计算"

【指导操作】
5.1 摘要：5步法提问→揉成草稿→提醒时态和不引文献
5.2 标题：让用户提供研究对象+方法+创新点→提供3种方案→严禁行为清单
5.3 关键词：讲解战略意义→给互补原则→检查数量

【与其他阶段的关系】
依赖阶段0-4全部完成，是全文的微缩标签
标题和关键词决定论文检索率和盲审专家匹配

【环节验收】
摘要：5要素齐全、缩写有全称、长度合规
标题：无标题党词汇、符合格式要求
关键词：与方法词互补、数量合规（4-6个）
→ 告知主Skill：阶段5完成
```

### 4.7 stage-6-finalize（致谢/参考文献）

```
【当前目标】
完成致谢和参考文献的规范化整理

【主要矛盾】
这部分没有认知障碍，但用户容易敷衍了事

【要素清单】
致谢：区分大论文/小论文风格
参考文献：全/高/准/群四大原则

【指导操作】
致谢："大论文真情流露，小论文简洁得体"
参考文献：导师可代劳格式化

【环节验收】
→ 告知主Skill：阶段6完成
```

### 4.8 stage-7-final-check（终极检查）

```
【当前目标】
通过口头复述检验全文逻辑

【主要矛盾】
用户写了全文但没从头到尾"讲"过一遍，逻辑漏洞未被发现

【指导操作】
"请你口头给我讲一遍你的研究——不需要看稿，凭记忆讲"

用户讲完后根据反馈修补逻辑断裂点

【环节验收】
→ 全部通过 → "论文可以进行修改打磨阶段了"
→ 告知主Skill：所有阶段完成
```

### 4.9 stage-ext-reviewer（审稿修回）

```
【当前目标】
理性拆解审稿意见，分门别类回复

【主要矛盾】
用户面对大量尖锐审稿意见时情绪失控+不知道从哪改起

【指导操作】
四分类法：
① 需要补充内容（实验/仿真重新跑）
② 需要澄清论点（文字辩护）
③ 结构性修改建议（图表重排）
④ 文笔性笔误（语法错别字）

【独立触发】
任何时候用户提到"审稿意见回来了""大修/小修""回复审稿人"时触发
```

## 五、创建顺序

建议按以下顺序创建子Skill：

```
第一批（核心基础）：
1. stage-0-initialize     ← 入口，必须先有
2. stage-1-methodology    ← 第一个正文阶段
3. stage-2-results        ← 核心阶段，最复杂

第二批（承上启下）：
4. stage-3-conclusion
5. stage-4-introduction   ← 依赖阶段2的映射表

第三批（收尾）：
6. stage-5-frontmatter
7. stage-6-finalize
8. stage-7-final-check

独立拓展：
9. stage-ext-reviewer

最后：
10. 主Skill SKILL.md      ← 需要知道所有子Skill的路径和接口
```

## 六、注意事项

1. 子Skill的YAML frontmatter中 description 要包含明确的触发词，表明"被主Skill调用时激活"
2. 主Skill的 description 要包含用户直接触发时的关键词
3. 子Skill之间不直接通信，所有跨阶段数据（如创新映射表）由主Skill维护和传递
4. 每创建完一个子Skill，应在主Skill中注册其路径和功能
5. 总行数控制：主Skill约100-150行，每个子Skill约80-200行
